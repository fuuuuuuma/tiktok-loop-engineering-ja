## 1. この資料で得られること（プレゼントの中身）

この動画・資料を受け取った人が、すぐ自分のTikTok運用に使えるように、3つのものを用意しています。

### ① ファイル構造のテンプレート（`CLAUDE.md`・`memory` など）

AIエージェント（Claude Codeなど）に「あなたはこういう方針で動いてね」を覚えさせる土台のセットです。`CLAUDE.md`（運用ルール）、`memory/`（学習の蓄積）、`skills/`（作業手順）といったフォルダ構成を、TikTok運用向けにあらかじめ組んであります。これを置くだけで、毎回ゼロから指示を書く必要がなくなります。

### ② TikTok運用で使えるSkills集

GitHubなどに公開されているTikTok関連のツール（MCP・OSS）を土台に、自分の運用に合わせて作り変えたSkill集です 🔶。たとえばトレンド取得・動画分析・字幕取得などの公開MCPが存在します（[出典](#17-出典)）。これらを「読みやすい手順書（SKILL.md）」としてまとめ直し、初心者でも呼び出せる形にします。

### ③ リサーチ→企画→動画→下書き投稿までを一気に進めるSkill

5工程をバラバラに動かすのではなく、「この商品でTikTok運用したい」と伝えるだけで、リサーチから下書き投稿の準備までを順番に進めるSkillです。各工程の「ノウハウ」はリサーチで詰め込みつつ、最終的に何を出すか・どう見せるかは本人が解説・判断する設計にしています。

> ※ プレゼントはあくまで「仕組みのテンプレート」です。成果（再生数・売上など）を保証するものではありません。使い方や題材によって結果は変わります。

## 2. なぜ今TikTokなのか — 認知・市場・TikTok Shop

### 商品・サービスを広げる最初の壁は「知ってもらうこと」

どんなに良い商品やサービスでも、知られていなければ売れません。マーケティングの順番でいえば、購入や申し込みの前には「認知（知ってもらう）」が来ます。そして近年、その認知を取る場所としてSNS・ショート動画の比重が増えています。

- ブランドを知るきっかけとして「ソーシャルメディア広告」が占める割合は **約29.7%**（2024年Q3）で、ここ2年で最も伸びたチャネルとされています（GWI / DataReportal調べ）🔶。
- 若年層ほど、ブランドを知るきっかけとしてソーシャルメディアの比重が大きいとされています 🔶。

つまり「まず認知を取る」なら、若い世代ほどSNSショート動画が効きやすい、という流れがデータでも見えてきています。

### TikTok市場は今が伸びどき

- 日本のTikTok月間アクティブユーザーは **4,200万人を突破**（TikTok Japan公式・2025年11月27日発表）。日本人の約3人に1人が使っている計算です ✅。
- 世界の月間アクティブユーザーは **約19〜20億人** と推計されています（第三者メディアの推計値）🔶。
- 日本でTikTokに広告を出す企業は **48万社超**、創作するクリエイターは **226万人超** とされています（TikTok公式レポート）✅。

### TikTok Shop — 「見て、その場で買う」が日本でも始まった

- **TikTok Shopは日本で2025年6月30日に正式提供開始**しました（TikTok公式）✅。動画やライブで商品に出会い、アプリ内で購入まで完結する「ディスカバリーEコマース」として展開されています。
- 提供開始から半年（2025/6/30〜2025/12/31）で、**流通総額の約70%が動画・ライブなどのコンテンツ起点**、登録セラーは約 **5万店**、TikTok Shopクリエイターは約 **20万人**、購入ユーザー数は **20倍以上** に増加したと公式が発表しています（2026年2月3日）✅。
- アメリカでは一足先に **2023年9月** にローンチ済みで ✅、東南アジアが最大市場とされています 🔶。

「短い動画で知ってもらう → その場で買ってもらう」という流れが、日本でも現実になってきた——これがTikTokを今やる理由です。

## 3. AIで運用しても伸びない理由

AIを使ったTikTok運用は、もちろん可能です。台本生成、AI音声、AIアバター、動画生成——道具はそろっています。ただ「今までのように使う」だけでは、伸びにくいし、結局は時間効率も良くなりません。理由は3つあります。

### 理由1：未開示・低品質なAI量産はプラットフォームに抑制される

TikTokは、AIで作った（または大きく加工した）写実的なコンテンツに **ラベル表示を必須** にしています ✅。さらにC2PA（Content Credentials）というメタデータで **自動的にAIラベルが付く** 仕組みがあり、ラベルを偽る・隠すといった行為は規約違反でコンテンツ削除の対象です ✅。また、使い回しや低品質な非オリジナル動画は、アルゴリズムで表示が抑えられるとされています 🔶。

ポイントは「AIだから嫌われる」のではなく、**未開示・非オリジナル・低品質な"量産"** が引き金になるという点です。

### 理由2：そもそも完了率の壁を超えられない

TikTokのアルゴリズムは、視聴維持時間・完了率・リピート・シェアを最も重視するとされています（Hootsuite）✅。冒頭の数秒でつまずく動画は、そもそもテスト配信の段階で失速します。OpusClipが1,350万本のクリップを分析した報告では、冒頭の数秒で離脱が集中し、最初の数秒で惹きつけられるかどうかが配信を大きく左右するとされています 🔶。「viral到達には完了率70%前後が目安」という業界解釈もあります（公式数値ではない）⚠️。

中身を考えずにAIで量産した動画は、この「最初の数秒」と「最後まで見られる構成」を作り込めず、量を出しても伸びないのです。

### 理由3：手間が減らない

AIで一部を速くしても、リサーチ・企画・編集・投稿・分析がバラバラだと、人が間をつなぐ作業が残ります。プロンプトを書き、出力を確認し、修正を指示し、また確認する——この往復が積み重なって、結局「時間効率はそんなに良くない」となりがちです。

> Xでも「生成AIコンテンツはオワコン」「量産型AI動画はアルゴリズムに淘汰されつつある」といった声が出ています（個人の発信・⚠️一意見）。"とりあえずAIで量産"の限界は、現場の温度感としても表れています。

## 4. ループエンジニアリングとは

### 「1回お願いする」から「自走するループ」へ

ループエンジニアリングは、AIエージェントを **「1回の指示で1回の出力」ではなく、「ゴールに向かって自分で繰り返す」** ように設計する考え方です 🔶。中身をかみくだくと、こうなります。

1. **ゴールを決める**（何ができたら完了か、を具体的に書く）
2. **自走させる**（AIが作業 → 自分で達成判定）
3. **自己検証する**（別の視点で「本当にできてる？」をチェック）
4. **未達なら修正して、また回す**

ふつうのAIの使い方は「お願い → 出力 → 自分で確認 → また指示」の繰り返しを人がやります。ループエンジニアリングは、この往復を **エージェント側に持たせる** わけです。

### なぜ「自己検証（チェック役）」が肝なのか

良いループの心臓部は「作る役（generator）」と「チェックする役（evaluator）」を分けることです 🔶。同じAIが作って自分でOKを出すと、つい甘くなります。作る役とは別に、達成基準を満たしているかを判定する役を置き、合格したときだけ止める——この仕組みがあると、人が毎回見張らなくても品質が保てます。

### `/goal` という入口

2026年にこの考え方を実装する代表例として、Claude Codeの `/goal`（完了条件を設定し、達成するまで自走しながら経過ターン・時間・トークンを追跡する仕組み）がよく挙げられます 🔶。「100点が出るまで検証と修正を繰り返す」を、この `/goal` で回します（→[第10章](#10-goal-で100点まで検証ループを回す)）。

> ⚠️ 用語の注意：「ループエンジニアリング（loop engineering）」は、特定の企業が公式に定義した名称ではありません。2025〜2026年にかけて実践者コミュニティの中で広まった呼び方です。便利な整理ですが、「〇〇社の公式用語」とは言い切れない点に注意してください。

## 5. 全体像 — Grill-meから分析までのパイプライン

この運用は、次の流れで一本につながっています。各工程の「ノウハウ」はリサーチで詰め込み、最終的な中身・見せ方は本人が解説・判断します。

```
Grill-me（前提の聞き出し）
   ↓
① リサーチ（複数の専門エージェント）
   ↓
② 企画作成（複数案 → 敵対的5体で議論 → 多数決）
   ↓
③ 動画作成（Runway / HeyGen / Higgsfield などと連携）
   ↓
④ 下書き投稿（Playwright / Computer Use・公式API）
   ↓  ← ここまでを /goal で「100点」まで検証・修正ループ
⑤ 分析（「分析したい」の一言 → データ取得 → 結果を保存）
```

### Grill-me — まず「何を売りたいか」を徹底的に聞き出す

最初にやるのは、**Grill-me（グリルミー）= 本人を質問攻めにして前提を引き出す** ステップです。ここで固めるのは次のような点です。

- 何を売りたいのか（商品・サービス・自分自身のブランディング）
- どういう導線設計か（TikTok → どこへ誘導するか。プロフィール / 公式LINE / TikTok Shop / ECなど）
- 誰に届けたいのか（ターゲット）
- 顔出しするのか、アバターで行くのか
- 使えるツール・予算・投稿頻度の前提

ここがズレたまま動くと、後工程が全部ズレます。だから最初に「壁打ち」で徹底的に言語化してから、各工程に入ります。

## 6. 工程①リサーチ（複数の専門エージェント）

### 1体ではなく複数体で、鮮度と質を上げる

リサーチは、1体のAIにまとめて任せるより、**リサーチ専門のエージェントを複数体** 同時に走らせるほうが、情報の鮮度と質が上がります。たとえば次のように担当を分けます。

- 「市場・トレンド」担当（最新の伸びている題材・ハッシュタグ・季節性）
- 「競合・お手本」担当（同ジャンルで伸びている動画の構成を分解）
- 「アルゴリズム・運用ルール」担当（最新の仕様・規約・注意点）

それぞれが別の角度から調べ、最後に突き合わせることで、1体では見落とす情報を拾えます。

### リサーチで押さえるアルゴリズムの要点（2026年）

- 最重視されるのは視聴維持時間・完了率・リピート・シェア（Hootsuite）✅。
- 冒頭の数秒が勝負。最初の数秒の離脱率が配信を大きく左右する（OpusClip・1,350万本分析）🔶。
- 投稿頻度は1日1〜4回がよく挙げられる目安。ただし回数より「一貫して続ける」ことが重要とされる（Buffer は週2〜5投稿を推奨）🔶。
- 2026年は「ハッシュタグよりキーワード」。キャプション・画面テキスト・音声をアルゴリズムが解釈し、検索性が重視される（Hootsuite / Sprout Social）✅。

> 大事なのは「調べた内容をそのまま貼る」のではなく、本人が腹落ちした言葉で解説できる状態まで噛みくだくこと。リサーチは詰め込み、語りは本人、が基本姿勢です。

## 7. 工程②企画作成（敵対的サブエージェント5体＋多数決）

### 企画案は「1つ」ではなく「複数」出す

企画はAIに1案だけ出させると、無難で平均的なものに寄りがちです。だから **複数案** を出させます。リサーチ結果をもとに、切り口・フック・ターゲットを変えた案を並べます。

### 敵対的な5体で議論させ、多数決をとる

次に、出した企画案を **敵対的なサブエージェント5体** に議論させます。「敵対的」というのは、それぞれが違う立場から厳しく突っ込む役、という意味です。たとえば：

- 視聴者目線で「最初の3秒で見るのをやめる理由」を探す役
- アルゴリズム目線で「完了率が落ちる箇所」を指摘する役
- 規約・炎上リスクを点検する役
- 導線目線で「結局その案で売れるのか」を問う役
- 競合との差別化を疑う役

それぞれが各案を採点・批判し、最後に **多数決** で残す案を決めます。1つのAIの「これがいいと思います」より、複数の厳しい目を通したほうが、企画の精度が上がります。

> この「複数案 → 敵対的レビュー → 多数決」は、第4章で触れた「作る役とチェック役を分ける」の応用です。チェック役を1体ではなく5体にして、合議で決める形です。

## 8. 工程③動画作成（Runway / HeyGen / Higgsfield などのMCP連携）

動画生成の環境がまだ無い場合は、AI動画生成ツールをエージェントから呼び出せるように **MCP連携** を組むのがおすすめです（もちろん、すでに使っている環境があればそれでも構いません）。

### 主なAI動画生成ツール（2026年）

| ツール | 主力機能 | エージェント連携 | 料金の概観 |
|---|---|---|---|
| **Runway**（Gen-4 / 4.5）| テキスト/画像→動画、リップシンク、Motion Brush、縦型対応 ✅ | 公式API＋公式MCP 🔶 | Web版 月$12〜・無料枠あり 🔶 |
| **HeyGen** | AIアバター動画、リップシンク、動画翻訳・吹き替え、写真アバター ✅ | 公式MCP（OAuth）＋Skills＋API ✅ | APIは従量（無料枠なし）／Web無料は月3本 🔶 |
| **Higgsfield** | 30以上のモデルのハブ、画像4K・動画15秒・一貫キャラ・バイラル予測 ✅ | 公式MCP（`mcp.higgsfield.ai/mcp`）APIキー不要・要アカウント認証 ✅ | クレジット制 🔶 |
| Sora 2（OpenAI）| 物理表現・音声同期 ✅ | API（2026年9月終了予定）⚠️ | 移行先を検討 |
| Veo 3.1（Google）| 4K・ネイティブ音声/効果音 🔶 | API（Google基盤）| 変動・要確認 ⚠️ |
| Kling 3.0 | マルチショット・多言語リップシンク・短尺向き 🔶 | API有 | 最安級・変動 ⚠️ |

### どう選ぶか（用途別の目安）

- **顔出ししたくない／アバターで話させたい** → HeyGen（アバター＋リップシンク）
- **実写風・動きのある映像が欲しい** → Runway / Veo 3.1
- **いろいろなモデルを1か所から試したい** → Higgsfield（30以上のモデルをまとめて呼べる）

たとえばClaude CodeにHiggsfieldのMCPを追加するコマンドは次のような形です（公式情報・2026年時点）🔶：

```bash
claude mcp add --transport http --scope user higgsfield https://mcp.higgsfield.ai/mcp
```

> ⚠️ 料金・無料枠・対応モデルは変動が激しい項目です。実際に使う直前に、各ツールの公式ページで最新を確認してください。この資料の価格は「目安」です。

ここでも、動画の中身（誰が・何を・どんなトーンで話すか）は本人が決め、生成と組み立ての作業をエージェントに任せる、という分担にします。

## 9. 工程④下書き投稿（Playwright / Computer Use と公式API）

### 「自動投稿」ではなく「下書きまで」を自動化する

ここは誤解されやすいので、はっきり書きます。狙うのは **「下書き保存（投稿の一歩手前）までを自動化」** で、最後に公開ボタンを押すのは人です。理由は、自動の本投稿はリスクと制約が大きいからです。

### 公式APIでできること・できないこと

- TikTokの公式 **Content Posting API** には、投稿せずに下書きとして送る **「Upload to Inbox（受信箱に下書き）」モード** があります ✅。ユーザーはアプリの通知をタップして、アプリ内で最終編集・投稿を完了します（＝**最後の投稿は人の手** が前提）✅。
- ただし **審査（audit）を通していないアプリからの投稿は、すべて非公開（自分だけ）に限定** されます。完全自動の公開投稿には、TikTokの審査通過が必要です ✅。
- レート制限の目安：アクセストークンごと毎分6リクエスト、アップロードURLは発行から1時間有効、24時間あたりの保留は最大5件 ✅。

つまり個人運用なら「APIで下書き／非公開保存 → アプリで人が最終公開」が現実的、という結論になります。

### Playwright / Computer Use を使う場合の注意

ブラウザを自動操作する Playwright や Computer Use でも下書き作成は技術的に可能ですが、**ログイン状態の維持とbot検知が本質的な壁** です 🔶。TikTokの利用規約はbotや自動スクレイピングを禁止しており ✅、自動化が検知されるとシャドウバンや一時／恒久停止のリスクがあります 🔶。

> この方針は、運用全体のルールとも揃っています——「YouTubeへの投稿は手動（BAN対策）」「Xの下書き保存はブラウザを使い捨てる仕組みのため自動化できず手動」。**生成・保存までを自動化し、最終的な公開判断は人がやる**、が安全な線引きです。

## 10. /goal で「100点」まで検証ループを回す

ここまでの工程（リサーチ→企画→動画→下書き）を、バラバラの単発作業で終わらせないために、**`/goal` を使って「複数のサブエージェントが100点を出すまで検証と修正を繰り返す」** ようにします。

### イメージ

1. ゴールを宣言する（例：「この企画で、冒頭3秒のフックと完了率を満たす下書きが、チェック役全員からOKをもらえること」）
2. エージェントが作業して、いったん成果物を出す
3. チェック役（複数）が採点する。1人でも基準未達なら差し戻し
4. 修正してまた採点……を、全員がOK（=100点）を出すまで繰り返す
5. 達成したら自動で停止

このとき大事なのが、**「100点」が何かを最初に具体的に決めておく** ことです。「いい感じ」では止まりません。「冒頭3秒に結論がある」「導線リンクが正しい」「規約NGワードが無い」のように、テストできる形で書きます。これが第4章の「ゴールを具体的に」の実践です 🔶。

## 11. 工程⑤分析（「分析したい」の一言から）

### 起動は「分析したい」だけ

投稿後の振り返りは、**「分析したい」の一言で開始** できるようにしておきます。あとはエージェントが、必要なアナリティクスデータ（再生数・視聴維持率・完了率・シェア・保存・流入元など）を求めてきます。

### 流れ

1. 「分析したい」と伝える
2. エージェントがアナリティクスのデータ（画面のスクショや書き出しCSVなど）を要求
3. データを渡すと、伸びた要因・落ちた箇所・次に試すことを整理
4. **分析結果を保存** して、次の企画（工程②）に活かす

これで「投稿して終わり」ではなく、**分析 → 次の企画 → また分析** という学習のループが回り始めます。運用が回数を重ねるほど賢くなる、という状態を作るのが目的です。

> 分析専用のエージェント（数値の4象限分析など）を別に用意しておくと、毎回同じ観点で比較でき、改善判断がぶれません。

## 12. ファイル構造テンプレートの中身

プレゼント①の「ファイル構造テンプレート」は、ざっくり次のような構成です（あくまで一例。自分の運用に合わせて足し引きします）。

```
tiktok-loop/
├── CLAUDE.md            # 運用ルール（トリガー→アクション形式）
├── memory/
│   ├── MEMORY.md        # 学習の索引（毎回読む）
│   ├── algorithm.md     # アルゴリズム・規約の最新メモ
│   ├── audience.md      # ターゲット・導線設計
│   └── results.md       # 投稿ごとの結果と学び
└── skills/
    ├── research/        # リサーチ工程
    ├── plan/            # 企画工程（複数案→敵対レビュー）
    ├── video/           # 動画生成（MCP連携）
    ├── draft-post/      # 下書き投稿
    └── analyze/         # 分析
```

### それぞれの役割

- **`CLAUDE.md`**：エージェントの「行動契約」。「Xを検索してと言われたら即実行する」「自動投稿はしない」のように、トリガーとアクションをルール化します。自己紹介ではなく、毎回守らせたい挙動だけを書くのがコツです。
- **`memory/`**：やりとりをまたいで覚えておきたいことを置く場所。アルゴリズムの最新メモ、ターゲット、過去の投稿結果などを蓄積します。`MEMORY.md` はその索引で、毎回最初に読み込みます。
- **`skills/`**：工程ごとの手順書（SKILL.md）。「この工程ではこう動く」を書いておくと、毎回指示しなくても同じ品質で動きます。

このテンプレートがあると、新しい題材でも「土台はそのまま、中身だけ差し替える」運用ができます。

## 13. 使い方（初心者基準）

専門用語が苦手でも大丈夫です。やることは「お願いする」だけ。あなたは"監督"で、作業はエージェントがやります。

### こんな悩み → こう頼むだけ

| こんな悩み | こう頼むだけ |
|---|---|
| 何から始めればいいか分からない | 「TikTokで〇〇を売りたい。まず前提を質問して」（Grill-meが始まります） |
| ネタ・トレンドが分からない | 「この商品で伸びそうな企画を、リサーチして複数案出して」 |
| どの企画がいいか選べない | 「出た企画案を、厳しい目で議論して多数決で1つ選んで」 |
| 動画を作るのが大変 | 「選んだ企画で、アバター動画の素材を作って」 |
| 投稿の準備が面倒 | 「下書きまで用意して。公開は自分でやる」 |
| 伸びたか分からない | 「分析したい」（→必要なデータを聞かれます） |

### そのままコピペで試せるプロンプト例

```
# まずは前提の聞き出しから
> TikTokで「(あなたの商品/サービス)」を広めたい。
  売りたいもの・導線・ターゲット・顔出しの有無を、ひとつずつ質問して。

# リサーチ＋企画
> 上の前提をもとに、伸びそうな企画を3案。
  各案に「冒頭3秒のフック」と「狙う完了率の工夫」を付けて。

# 分析（投稿後）
> 分析したい
```

### 比喩で言うと

あなたは料理人ではなく **オーナー** です。「こういうお店にしたい」「この客層に」を伝えれば、仕込み（リサーチ・企画・制作・下書き）はスタッフ（エージェント）が回します。あなたは味見（最終チェック）と「お店の方針」を決めることに集中できます。

## 14. 注意点 — 規約・自動投稿・誇張表現

仕組み化はとても便利ですが、守るべき線引きがあります。

- **自動の本投稿はしない**。下書き・非公開保存までにとどめ、公開は人が判断する。TikTokの規約はbotや自動化を禁止しており、検知されるとシャドウバンや停止のリスクがあります ✅🔶。
- **AI生成は隠さない**。写実的なAIコンテンツはラベル表示が必須で、未開示は規約違反です ✅。正直に開示するほうが、長期的に安全です。
- **数字や成果を盛らない**。「稼げると断定する」「バズると保証する」ようなことはしません（景品表示法の観点でもリスク）。再生数・売上は題材や運用しだいで変わります。
- **量より、最後まで見られる設計**。完了率を満たせない量産は伸びません。1本ずつ「最初の3秒」と「最後まで」を作り込むほうが結果につながります。

## 15. FAQ

**Q. プログラミングの知識がないと無理ですか？**
A. いいえ。基本は「お願いする」だけです。テンプレートとSkillを置いておけば、専門用語を使わずに各工程を呼び出せます。難しい設定は最初の1回だけで、あとは使い回せます。

**Q. 本当に時間が短くなりますか？**
A. 工程をつなげて自走させるぶん、人の往復作業は減らせます。ただし具体的な短縮幅は題材・環境・慣れで変わるため、断定はできません（誇張・保証はしません）⚠️。

**Q. 完全に自動で投稿までやってくれますか？**
A. やりません。下書き・準備までを自動化し、公開は人が押す設計です。これは規約とアカウントを守るための、意図した線引きです ✅。

**Q. AIで作った動画はバレて不利になりませんか？**
A. 「AIだから」不利なのではなく、「未開示・低品質・使い回し」が抑制の引き金です ✅。正しく開示し、最後まで見られる動画を作れば、過度に恐れる必要はありません 🔶。

**Q. どのAI動画ツールを使えばいいですか？**
A. 顔出しなしならHeyGen（アバター）、実写風ならRunway/Sora/Veo、いろいろ試すならHiggsfield、が目安です。料金は変動するので、使う直前に公式で確認してください ⚠️。

**Q. ループエンジニアリングって難しそうです。**
A. 名前は難しそうですが、中身は「ゴールを決めて、できるまでAIに繰り返させる」だけです。`/goal` に完了条件を渡すところから始められます 🔶。
